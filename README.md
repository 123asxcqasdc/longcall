# LongCall 98

Лёгкое приложение для **аудиозвонков** в оформлении Windows 9x: рабочий стол, окна с
тильдой, панель задач, «Пуск» и синий прогресс-бар с бегущими «шашечками».

Работает и в браузере, и как настольное приложение для **Windows и Linux** (Electron) —
в обёртке вместо рабочего стола настоящие окна операционной системы.

Только звук, до **4 человек** в комнате, без установки и без паролей.
Хостинг веб-версии — GitHub Pages (статика) на своём домене, сигналинг — Firebase Realtime Database, звук — WebRTC.

```
https://longcall.c6t.ru/
```

## Что внутри

| Возможность | Как сделано |
| --- | --- |
| Локальный аккаунт | Ник хранится в `localStorage`, идентификатор — в cookie `lc_uid` и в Firebase-анониме. Пароля нет, восстановления нет |
| Главное окно | Описание приложения, профиль, кнопка «Создать звонок», вход по коду, история звонков |
| Недавние звонки | `users/{uid}/recent` в Realtime Database: доступны с любого устройства, где выполнен вход |
| Групповой звонок | WebRTC full mesh (каждый с каждым), до 4 участников |
| Индикатор речи | `AnalyserNode` + RMS по локальному и каждому удалённому потоку |
| Прогресс-бар Win9x | Загрузка приложения, вход в комнату, смена микрофона, загрузка истории |
| Языки | Русский и английский, переключатель в меню и в настройках |
| Звуки | Синтезируются через Web Audio, внешних файлов нет |
| Чат звонка | `rooms/{code}/chat` в той же базе: сообщения до 500 символов, панель вместо журнала, счётчик непрочитанных, работает при выключенном микрофоне |
| Файлы звонка | До 8 МБ на файл и до 12 файлов на комнату, части в `rooms/{code}/fileparts`, просмотр картинок, видео и текста на месте |
| Быстрая отправка | `Ctrl+V` с картинкой или файлом из буфера и перетаскивание файла в окно — тот же `RoomFiles.send()` |
| Своё оформление | Свой CSS поверх стандартного: «Вид → Своё оформление…», хранится в `localStorage` (`lc.css`), применяется до отрисовки |

## Приложение для Windows и Linux (Electron)

Веб-версия живёт на GitHub Pages, но тот же код собирается в настольное приложение.
Главное отличие — **в обёртке нет «рабочего стола»**: каждое окно приложения это
настоящий `BrowserWindow` без системной рамки, а заголовок в стиле Win98 работает
как drag-зона (перетаскивание, двойной клик — развернуть).

| Что | Как сделано |
| --- | --- |
| Главное окно | `BrowserWindow` 720×720 (мин. 460×420), позиция запоминается в `userData` |
| Окно звонка | отдельный `BrowserWindow` на комнату, сразу подключается к ней; размеры свои |
| Кнопки `_ □ ×` | реальные `minimize` / `maximize` / `close` через IPC |
| Рамка | `frame: false`; перетаскивание — CSS `-webkit-app-region: drag` |
| Экран запуска | тот же, что в браузере: окно «LongCall 98» с прогресс-баром на всё окно; главный экран появляется только после подключения аккаунта |
| Закрытие окна звонка | приложение сначала выходит из комнаты (`onDisconnect` успевает сработать), потом окно закрывается |
| Микрофон | разрешение `media` выдаётся только на `audio`, видео запрещено |
| Хранение | `localStorage`/cookie работают, потому что страницы отдаются по защищённой схеме `app://longcall`, а не `file://` |
| Ссылка на комнату | всегда собирается от адреса сайта (`SITE_URL`), поэтому в буфер обмена попадает обычный `https://…/?room=1234`, даже когда звонок открыт в приложении |
| Переход в приложение | схема `longcall://join?room=1234`: приложение регистрирует её в системе (`protocols` в `package.json`), а веб-страница показывает в приглашении кнопку «Открыть в приложении» |
| Безопасность | `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, узкий preload-мост, внешние ссылки — в системный браузер |

### Запуск из исходников

```bash
npm install      # ставит electron, electron-builder и esbuild
npm start        # или npm run dev — с логами
```

Нужен Node.js 20+ и рабочий звук (на Linux — PipeWire или PulseAudio).

### Сборка установщиков

```bash
npm run dist:linux   # AppImage + .deb  → release/
npm run dist:win     # установщик (setup.exe) + portable.exe → release/
```

Установщик Windows — классический мастер в стиле Windows 98: боковая панель 164×314
с пиксельной иконкой, шапка страниц 150×57, системный серый фон и тексты вроде
«Добро пожаловать в мастер установки LongCall 98». Картинки генерирует
`tools/make-icons.py`, разметка мастера — `electron/installer.nsh`
(подключается через `build.nsis.include`).

| Файл | Что это |
| --- | --- |
| `longcall98-1.2.0-setup.exe` | мастер установки (NSIS, `oneClick: false`) |
| `longcall98-1.2.0-portable.exe` | запуск без установки |
| `longcall98-1.2.0-x86_64.AppImage` | Linux, без установки |
| `longcall98-1.2.0-amd64.deb` | Linux, Debian/Ubuntu |

Workflow [`.github/workflows/desktop.yml`](.github/workflows/desktop.yml) собирает оба
варианта на GitHub-раннерах и прикрепляет файлы к релизу при пуше тега `v*`:

```bash
git tag v1.2.0 && git push origin v1.2.0
```

Иконки пересобираются скриптом `tools/make-icons.py` (нужен Pillow, только для разработки):

```bash
python3 -m venv .venv && .venv/bin/pip install pillow
.venv/bin/python tools/make-icons.py
```

Windows-сборка не подписана — SmartScreen может показать предупреждение.
Кросс-компиляция делается на соответствующей ОС: на Linux собирается Linux, на Windows — Windows.

### Ссылки между веб-версией и приложением

- Ссылка на комнату, которую копирует кнопка «Ссылка», — обычный адрес сайта:
  `https://longcall.c6t.ru/?room=1234`. В приложении она больше не
  превращается в `app://longcall/…`.
- Открыть комнату в установленном приложении можно по ссылке
  `longcall://join?room=1234` — в браузере для этого есть кнопка «Открыть в приложении»
  в окне приглашения. Если приложение не установлено, ничего не произойдёт,
  и звонок останется в браузере.
- Приложение понимает ссылку и при запуске (аргументы командной строки),
  и когда уже работает (`second-instance`), и на macOS (`open-url`).
- Формы ссылки: `longcall://join?room=1234`, `longcall://join/1234`,
  `longcall://room/1234`, `longcall://1234` и старый `--room=1234`.
  Ссылка на уже открытую комнату поднимает её окно, а не создаёт второе.
- Регистрация схемы: на Windows — установщик NSIS (`protocols` в `package.json`)
  плюс `setAsDefaultProtocolClient` при старте (важно для portable-сборки);
  на Linux `.desktop` с `MimeType=x-scheme-handler/longcall` пишется при первом
  запуске в `~/.local/share/applications` и вызывается `xdg-mime default` —
  без этого AppImage вообще не открывал бы ссылки.

### Панель окна

Окно без системной рамки, поэтому все действия — на собственной панели
заголовка: значок, название, кнопки «свернуть», «развернуть», «закрыть»
(высота 22 px, кнопки 20×16 — попадать мышью легко).

- Перетаскивание: `-webkit-app-region: drag` на Windows/macOS и X11, а на Linux
  дополнительно ручное — `js/desktop.js` шлёт `desktop:drag-start`/`drag-end`,
  главный процесс двигает окно по курсору (`screen.getCursorScreenPoint`).
  Это работает и под Wayland, где встроенное перетаскивание Electron
  игнорируется.
- Восстановление позиции: сохранённые координаты проверяются на попадание в
  рабочую область мониторов. Если окно оказалось бы за экраном (сменился
  монитор, тайловый WM, другая сессия), оно открывается по центру, а размер
  обрезается по экрану — панель с кнопками не может «уехать» за край.
- Если событие `ready-to-show` не пришло, окно всё равно показывается через
  4 секунды — вместо невидимого процесса.

### Звонки через строгие сети (TURN)

STUN только сообщает адреса; если участник за симметричным NAT, CGNAT мобильного
оператора или корпоративным файрволом, прямой канал невозможен и нужен
ретранслятор TURN.

`js/config.js` + `js/turn.js`:

- **STUN**: Google (2 адреса), Cloudflare, Open Relay.
- **TURN**: `staticauth.openrelay.metered.ca` (Open Relay от Metered, 20 ГБ/мес).
  Статический логин `openrelayproject/openrelayproject` провайдер отключил, поэтому
  креды **подписываются в браузере**: `username = "<expiry>:longcall"`,
  `credential = base64(HMAC-SHA1(secret, username))` через WebCrypto, срок 12 часов,
  кэш один час. Порты 80, 443, `?transport=tcp` и `turns:` (TLS) — последние
  проходят там, где разрешён только HTTPS.
- **Запасной вариант**: `freeturn.net` (сторонние креды) и STUN — если WebCrypto
  недоступен, звонок не ломается, просто остаётся без ретранслятора.

Соединение идёт с `iceTransportPolicy: "all"`: сначала пробуется прямой канал,
ретранслятор — запасной путь. В журнале звонка видно `ICE ник: host 2 · srflx 1 · relay 2`
и `канал: relay (udp)` — то есть идёт ли звук через ретранслятор.

### Диагностика: отчёты в Firebase

Когда соединиться не удалось, отчёт собирается и отправляется **автоматически**
(после исчерпания перезапусков ICE). Вручную — «Справка → Отправить отчёт о проблеме…».

Что внутри отчёта (`js/diagnostics.js`):

- версия приложения, платформа (браузер/Electron, ОС, Chrome/Electron-версия),
  часовой пояс, разрешение экрана, `navigator.onLine`;
- набор ICE-серверов **без паролей**, признак `turn: signed|static|none` и причина;
- по каждому участнику: вежливость, типы кандидатов `host/srflx/relay`, время до
  первого кандидата, история `iceGatheringState`/`iceConnectionState`/`connectionState`;
- `getStats()`: какая пара выбрана — `direct` или `relay`, протокол, до 12 пар;
- ошибки `getUserMedia` и `negotiate`, таймлайн до 120 событий с миллисекундами.

Приватность: пароли TURN, ник и uid не сохраняются (uid хешируется SHA-256), SDP и
IP-адреса кандидатов не пишутся — только типы и счётчики.

Куда: `logs/{room}/{pushId}`. Если правила базы не разрешают запись — автоматически
в `users/{uid}/diagnostics/{pushId}` (этот путь разрешён текущими правилами).
Короткий код отчёта показывается в тосте и в журнале звонка.

> В `database.rules.json` добавлен узел `logs`. Чтобы отчёты попадали именно в
> `logs/{room}`, правила нужно задеплоить: `firebase deploy --only database`.
> Без деплоя отчёты сохраняются в запасной путь `users/{uid}/diagnostics`.

### Файлы прямо в звонке

Кнопка **«Файлы»** на панели звонка (или «Звонок → Файлы звонка…») открывает окно
комнаты: отправить файл, список файлов всех участников, «Скачать» и «Удалить».

- **Один файл за раз.** Пока идёт отправка, вторая кнопка отвечает «сначала дождитесь
  конца текущей отправки».
- **Лимиты:** до 8 МБ на файл и до 12 файлов на комнату (`APP.files` в `js/config.js`).
- **Куда пишется.** В ту же Realtime Database, что и сигналинг: файл режется на куски
  по 96 КБ и кодируется в base64, метаданные пишутся последними, поэтому остальные
  видят файл только целиком.

  ```
  rooms/{code}/fileparts/{fileId}/{part}   "…base64…"
  rooms/{code}/files/{fileId}              {name, size, type, from, nick, at, parts}
  ```

  Firebase Storage намеренно не используется: он потребовал бы отдельного сервиса и
  настройки CORS для домена GitHub Pages, а Realtime Database уже настроена.
- **Просмотр на месте.** Кнопка «Просмотр» (или клик по имени файла) открывает файл,
  не скачивая его:
  - `jpg`, `jpeg`, `png`, `gif`, `webp`, `bmp`, `avif`, `ico`, `svg` — картинка по ширине окна,
    под ней размеры в пикселях; если формат не открывается — понятное сообщение и «Скачать»;
  - `mp4`, `m4v`, `webm`, `ogv`, `mov` — встроенный плеер `<video>`;
  - `mp3`, `wav`, `ogg`, `m4a`, `aac`, `flac`, `opus` — плеер `<audio>`;
  - `txt`, `md`, `log`, `json`, `csv`, `ini`, `yml`, `srt` — моноширинное окно текста,
    первые 100 КБ (больше в DOM выводить нельзя — вкладка подвисает).

  Тип определяется по MIME, а если браузер его не знает — по расширению. Текст
  разбирается как UTF-8, а если замен слишком много — как Windows-1251: Блокнот
  Windows 9x сохранял именно так, и в UTF-8 такой файл выглядел бы «ромашками».
  Кодировка указывается под текстом. Blob-URL освобождается, а звук ставится на
  паузу при закрытии окна.
- **Удаление.** Всё лежит внутри комнаты, поэтому последний ушедший участник удаляет
  комнату вместе с файлами и их частями (`CallSession.leave`). Отправитель может
  удалить свой файл раньше — тогда удаляются и части.
- **Скачивание.** В браузере — обычное сохранение по ссылке; в настольном приложении —
  системный диалог «Сохранить как» через IPC `desktop:save-file`.
- **Приватность.** Файлы видит любой, кто знает код комнаты: отдельного пароля у
  комнаты нет. Для чувствительных документов лучше другое средство.

> Правила для `files` и `fileparts` добавлены в `database.rules.json` — нужен
> `firebase deploy --only database`. Без них кнопка «Отправить файл» ответит, что
> Firebase отклонил запрос (список файлов при этом не сломается).

### Чат прямо в звонке

Кнопка **«Чат»** на панели звонка (или «Звонок → Чат звонка») занимает место журнала
внизу окна: история сообщений, поле ввода и «Отправить». Чат нужен именно тогда,
когда микрофон выключен, говорить неудобно или связь плохая, а написать надо.

- **Где лежит.** `rooms/{code}/chat/{pushId}` = `{from, nick, text, at}` — та же
  Realtime Database, что и сигналинг. Отдельного сервиса нет.
- **Сколько видно.** Подписка читает последние 80 сообщений (`limitToLast`), порядок —
  по ключу, то есть по времени. Новое сообщение у закрытой панели поднимает счётчик
  на кнопке и подаёт короткий сигнал.
- **Ограничения.** 500 символов на сообщение, не чаще одного в секунду. Пустые
  сообщения не отправляются; переводы строк и лишние пробелы схлопываются.
- **Удаление.** Сообщения живут внутри комнаты, поэтому исчезают вместе с ней, когда
  уходит последний участник.
- **Приватность.** Чат видит любой, кто знает код комнаты, — как и остальное в комнате.

> В `database.rules.json` добавлен узел `chat`. Без `firebase deploy --only database`
> Firebase отклонит запись, и в журнале звонка появится «чат недоступен — проверьте
> правила базы».

### Файл из буфера или перетаскиванием

Два быстрых способа отправить файл, не открывая окно «Файлы звонка»:

- **`Ctrl+V`** — если в буфере картинка (скриншот, копия из проводника) или файл,
  он уходит в звонок. Обычный текст вставляется как обычно: перехватываются только
  файлы, поэтому вставка в поле чата работает штатно.
- **Перетаскивание** — файл, брошенный в окно, подсвечивает окно подсказкой
  «Отпустите, чтобы отправить в звонок» и уходит в звонок. Перетаскивание текста
  и ссылок не перехватывается.

Оба способа используют тот же `RoomFiles.send()`, что и кнопка «Отправить файл»:
полоса прогресса внизу справа, «Отменить» и очередь — по одному файлу за раз.
Лимиты и правила те же, что у файлов звонка.

### Своё оформление

Меню **«Вид → Своё оформление…»** (на главном экране и в окне звонка) открывает окно
с полем для CSS. Всё, что там написано, попадает в `<style id="userCss">` — последний
элемент в `<head>`, поэтому правила перекрывают оформление приложения.

- **Куда сохраняется.** В `localStorage` (`lc.css`, до 20 000 символов). Своего
  оформления у каждого своё: другие участники его не увидят, на сервер ничего не уходит.
- **Когда применяется.** Маленький скрипт в `<head>` ставит сохранённый css до загрузки
  стилей — тема восстанавливается без вспышки стандартного вида. Кнопка «Применить»
  работает сразу, без перезагрузки.
- **Что можно.** Перекрашивать что угодно: `.desktop`, `.win`, `.titlebar`, `.btn`,
  `.call-log`, `.chat-list`. Внутри приложения переменные оформления объявлены на
  `:root` (`--face`, `--navy`, `--bevel-out` и другие) — быстрее всего менять их.
- **Что нельзя.** Скрипты не исполняются: это обычный CSS, а не HTML. `@import`
  и `url()` работают так же, как в любом css, — внешние картинки браузер загрузит.
- **Если сломалось.** Откройте адрес с `?nocss` (`https://longcall.c6t.ru/?nocss`) —
  сохранённый css не применится, и в меню можно будет его исправить или очистить.
  Кнопка «Очистить» в том же окне удаляет его совсем.
- **Пример.** Кнопка «Вставить пример» подставляет тёмное оформление окна звонка —
  дальше можно править под себя.

### Как устроено

```
electron/main.cjs      главный процесс: окна, протокол app://, IPC, разрешения
electron/preload.cjs   мост contextBridge → window.longcallDesktop
electron/icons/        иконки: icon.png для окна, icon.ico для Windows, 16x16…512x512 для deb/AppImage
js/desktop.js          обёртка над мостом + no-op для браузера
css/desktop.css        режим обёртки: без рабочего стола, окно на весь BrowserWindow
```

Режим определяется по `navigator.userAgent` (`Electron/`) ещё в `<head>`, поэтому
«рабочий стол» не успевает мелькнуть. В браузере `js/desktop.js` работает как
заглушка и ничего не меняет — веб-версия остаётся прежней.

## Настройка Firebase (обязательно, один раз)

Приложение использует ваш проект `longcall`. Первый и третий шаги обязательны; второй —
только если появится вход через OAuth.

1. **Анонимный вход.**
   Firebase Console → Authentication → Sign-in method → включить **Anonymous**.

2. **Авторизованные домены — только если появится вход через OAuth.**
   Authentication → Settings → Authorized domains. Для анонимного входа этот список
   не нужен: `signInAnonymously` и Realtime Database ходят обычными REST-запросами,
   без редиректа через `authDomain`. Список понадобится, если однажды добавишь
   «Войти через Google» и подобное — тогда внеси `longcall.c6t.ru`.

3. **Правила базы данных.** Два равнозначных пути, достаточно одного.

   **Через консоль, без терминала.** Realtime Database → вкладка **Rules** → выделить
   всё в редакторе (Ctrl+A) → вставить содержимое [`database.rules.json`](database.rules.json)
   целиком, вместе с внешней скобкой `{ "rules": { … } }` → **Publish**.
   Готово, вступает в силу сразу.

   **Через терминал, если установлен [firebase-tools](https://firebase.google.com/docs/cli).**
   Команда выполняется на своём компьютере в папке репозитория (там, где лежат
   `firebase.json`, `.firebaserc` и `database.rules.json`), а не в браузере и не на сайте:

   ```bash
   npm install -g firebase-tools     # один раз
   firebase login                    # один раз, откроется браузер
   cd путь/к/папке/longcall           # корень репозитория
   firebase deploy --only database   # проект берётся из .firebaserc → longcall
   ```

   Проект уже прописан в `.firebaserc` (`longcall`), поэтому `--project` указывать не нужно.
   Если файл потерялся, добавь `--project longcall`. Ключ `--only database` важен:
   без него команда попытается задеплоить ещё и Hosting, а сайт живёт на GitHub Pages.

   В интерфейсе приложения эти шаги намеренно не показываются: настройка делается один раз.

Правила закрывают базу от анонимного интернета: читать и писать комнаты может только
авторизованный Firebase-пользователь, а свой профиль и историю — только их владелец.

## Локальный запуск

```bash
npm install            # только для пересборки Firebase SDK
npm run serve          # python3 -m http.server 8080
# http://localhost:8080
```

Микрофон браузеры разрешают только на `https://` или `localhost` — по IP в локальной
сети звонки не запустятся.

## Сборка Firebase SDK

SDK не тянется с внешнего CDN: он собран заранее в `vendor/firebase.js` (esbuild, ESM,
~250 КБ). Чтобы обновить версию:

```bash
npm run build:vendor
```

`tools/firebase-entry.js` перечисляет используемые функции, поэтому в бандл попадает
только нужное (auth + realtime database).

## Как устроен звонок

```
комната rooms/{code}
├── meta                 {createdAt, createdBy, maxParticipants, audioOnly}
├── participants/{uid}   {nick, joinedAt, muted}   ← presence через onDisconnect
├── signals/{to}/{msgId} {from, type: description|ice|bye, sdp|candidate, at}
├── files/{fileId}       {name, size, type, from, nick, at, parts}
├── fileparts/{fileId}/{n}  «…base64…»
└── chat/{pushId}        {from, nick, text, at}
```

* Топология — **full mesh**: каждый участник держит `RTCPeerConnection` с каждым.
  Для 4 человек это 3 потока на клиент, ~40 кбит/с каждый.
* Переговоры — по схеме *perfect negotiation*: участник с меньшим `uid` инициатор,
  с большим — «вежливый», поэтому одновременные offer'ы разводятся без конфликтов.
* ICE-кандидаты буферизуются до получения remote description; при `failed`/долгом
  `disconnected` выполняется `restartIce()` с нарастающей паузой.
* Последний ушедший участник удаляет комнату — база не копит мусор.
* Видео не запрашивается и не принимается: только `audio`.

### Ограничения, о которых честно

* **4 участника** — предел mesh-схемы. Для 10+ нужен SFU-сервер (не влезает в «Pages + Firebase»).
* **Файлы — до 8 МБ и до 12 на комнату.** Крупные файлы в Realtime Database не
  помещаются (10 МБ на одну запись, 1 ГБ на весь проект), так что это обмен
  документами и фотографиями, а не «скинуть фильм». Файл видит любой, кто знает
  код комнаты.
* **TURN — публичный бесплатный** (Open Relay с подписанными в браузере кредами,
  плюс запасной freeturn). В редких сетях он тоже может не пройти: тогда в журнале
  звонка будет подсказка, а отчёт уйдёт в Firebase автоматически.
* **Аккаунт локальный.** Очистка данных браузера удаляет профиль и историю.
  Восстановления по почте нет — это осознанный выбор в пользу входа «в один клик».
* **Чат и файлы видит любой, кто знает код комнаты**, — отдельного пароля у комнаты нет.
* **Правила БД** разрешают авторизованным пользователям читать любую комнату по коду:
  код комнаты работает как приглашение (4 цифры = 9000 вариантов, перебор возможен).
  Для приватных звонков используйте более длинные коды (см. `APP.roomCodeLength`).
* Firebase API-ключ в `js/config.js` публичен по дизайну. Рекомендуется ограничить его
  по HTTP-referrer в Google Cloud Console.

## Деплой

Workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) проверяет синтаксис,
собирает статику (без `.git`, `node_modules`, `tools`) и публикует её через `actions/deploy-pages`.

### Включение Pages (один раз, вручную)

Токен интеграции и `GITHUB_TOKEN` не могут создать сайт Pages — это делает владелец
репозитория, поэтому первый запуск workflow проходит без деплоя и оставляет подсказку:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Actions → Deploy to GitHub Pages → Re-run jobs** (или просто следующий пуш в `main`).

После этого сайт живёт на `https://longcall.c6t.ru/` и обновляется
автоматически при каждом пуше в `main`. Пока Pages не включён, сборка остаётся зелёной —
workflow проверяет доступность Pages API и пропускает шаги деплоя.

### Свой домен

Домен `longcall.c6t.ru` подключён к Pages как custom domain, а в корне лежит файл
[`CNAME`](CNAME) — он закрепляет адрес за сайтом и попадает в публикуемую сборку.

- DNS: `CNAME longcall → 123asxcqasdc.github.io` (у apex-домена — A-записи
  `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`).
- Pages → Settings → Custom domain: `longcall.c6t.ru`, затем «Enforce HTTPS».
  Сертификат выпускается автоматически и продлевается сам.
- Firebase → Authentication → Settings → **Authorized domains**: `longcall.c6t.ru`
  обязателен, иначе анонимный вход на новом домене не работает.

Ссылки на комнаты собираются из `SITE_URL` в [`js/config.js`](js/config.js) — это
единственное место, где записан публичный адрес приложения.

Альтернатива без Actions: Settings → Pages → Source: **Deploy from a branch** → `main` → `/ (root)`.
Сайт заработает сразу, но тогда workflow деплоя не нужен и его лучше отключить.
